# DuoForge: a world built together

## Purpose

DuoForge aims to become a living creative space where players, artists, game designers, storytellers and developers can collaborate on connected game worlds. It is not intended to be merely a button that produces disposable games.

## The collaboration loop — product vision

1. **Imagine:** describe a character, location, mission or world.
2. **Create:** build using reusable models, materials, mechanics and environments.
3. **Connect:** propose a contribution to an existing world with explicit permissions.
4. **Play:** experience a specific version on mobile or desktop.
5. **Review:** test and compare changes before publication.
6. **Grow:** preserve authorship and project identity as the world expands.

These steps describe our direction. They do not claim multi-user editing or automatic Sites/GitHub sync already works.

## The practical first milestone

Build a stable, permission-aware connection between existing Sites project IDs and GitHub revisions. A change should become an isolated playable preview tied to the precise commit. The owner reviews and approves before it can change a real project. Do not create parallel projects or copy the private Sites source.

## The GitHub story

GitHub is our engineering and communication layer: transparent experiments, version history, tests and reproducible public demos. DuoForge Sites remains the place where the game world lives and where creators and players belong.

**Success looks like:** a visitor can understand the purpose within a minute, reach the real games page with one click, experience a working game, and see honestly what is shipped versus planned.
